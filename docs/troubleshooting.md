# トラブル対応

- 接続エラー: ROSBRIDGE_HOST / PORT、既存rosbridgeの起動状態、ネットワーク到達性を確認します。
- バッテリーのタイムアウト: トピック名・型・publisherを確認します。読み取り失敗時には成功値を返しません。
- chatの設定エラー: OPENAI_API_KEY と LLM_MODEL を設定します。check / batteryには不要です。
- ROSA更新でrclpyのエラー: agentの独自ツール登録フックと上流APIの変更を確認します。ROSの導入で回避する設計ではありません。

## モック移動後に入力待ちが見えない

以前の版では背景の速度ログが `>` を押し流していました。現在の版ではチャット中の定周期ログを非表示にしています。実行中のCLIは終了して起動し直してください。開始応答の後は次の入力を受け付けます。`/status` で終了状態を確認できます。

## 移動が拒否される

- `rosbridge` の移動は既定で有効です。拒否される場合は `.env` やシェルの `ENABLE_MOTION=false` を確認してください。模擬操作は `.env` に `ROBOT_BACKEND=mock` を設定して起動し直してください。
- 方向別ツールの速度は有限の正値を指定します。並進合成速度は0.4〜0.9 m/s（停止の0は除く）、旋回は最大7.0 rad/s（既定5.0）、時間は0より大きく最大3秒です。
- 移動中の新しい移動は拒否します。時間終了を待つか、チャット内の `/stop` で取り消してください。
- 「前進して」だけでは継続時間が不明なので、時間の確認が入ります。「ゆっくり3秒間前進して」のように指定してください。

## 模擬移動のログを見たい

チャットでは `/status` を使います。速度指令の定周期ログは `.env` を `ROBOT_BACKEND=mock` に設定して、次のLLM不要コマンドで確認できます。

```sh
uv run rosa-turbopi move --vx 0.5 --duration 1
```

`state: failed` は実行や停止記録の失敗を示します。開始応答だけで完了したとは判断せず、状態と `error` を確認してください。
