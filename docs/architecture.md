# 構成

ROSA専用コンテナから既存rosbridgeへ接続します。既存TurboPiのコンテナ・起動設定・ソースを変更しません。Dockerソケットやベンダーコードをマウントしません。

ROSA 1.0.10の標準ツールはROS CLI・rclpyやシステム操作を前提とするため、`RosbridgeROSA._get_tools` をオーバーライドして明示的なツール一覧だけを返します。これは上流の内部フックに依存するため、更新時はアダプターのテストが必要です。`blacklist` はツール名の許可リストではありません。

LLMは操作の選択、robot層は実行、transport層は通信を担当します。初期版は読み取りのみです。通信エラーはCLIに返し、購読はタイムアウト後に解除します。

今後の走行実装: 有限の速度・時間、定周期送信、終了時ゼロ速度、動作の競合管理をrobot層へ追加します。ただしプロセス停止・通信断時の停止をクライアントだけで保証できません。既存制御側のタイムアウトを確認するまで走行ツールを公開しません。

## モック移動

MockTransportはメモリに指令を記録し、ネットワークを使いません。MotionExecutorはバックグラウンド実行・取消・ゼロ速度送信・状態とエラーの保持を担当します。並進合成速度と継続時間を検証し、重複移動を拒否します。終了時は停止を試みてから通信を閉じます。

調査した既存ROS・SDKコードには指令途絶の停止監視がありませんでした。基板ファームウェアの挙動は未確認です。またcmd_velに既存publisherがあり、競合対策も必要です。実機publishは未実装のままです。ベンダーコードは本リポジトリへ転載しません。
