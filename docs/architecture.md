# 構成

ROSA専用コンテナから既存rosbridgeへ接続します。既存TurboPiのコンテナ・起動設定・ソースを変更しません。Dockerソケットやベンダーコードをマウントしません。

ROSA 1.0.10の標準ツールはROS CLI・rclpyやシステム操作を前提とするため、`RosbridgeROSA._get_tools` をオーバーライドして明示的なツール一覧だけを返します。これは上流の内部フックに依存するため、更新時はアダプターのテストが必要です。`blacklist` はツール名の許可リストではありません。

LLMは操作の選択、robot層は実行、transport層は通信を担当します。実機バックエンドは読み取りのみ、モックは移動と停止にも対応します。通信エラーはCLIに返し、購読はタイムアウト後に解除します。

モックでは有限の速度・時間、定周期送信、終了時ゼロ速度、重複移動の拒否をrobot層で実装しています。実機への移動送信は未実装です。プロセス停止・通信断時の停止をクライアントだけで保証できないため、実機対応には停止仕様の確認と既存指令元との競合対策が必要です。

## モック移動

MockTransportはメモリに指令を記録し、ネットワークを使いません。MotionExecutorはバックグラウンド実行・取消・ゼロ速度送信・状態とエラーの保持を担当します。並進合成速度と継続時間を検証し、重複移動を拒否します。終了時は停止を試みてから通信を閉じます。

調査した既存ROS・SDKコードには指令途絶の停止監視がありませんでした。基板ファームウェアの挙動は未確認です。またcmd_velに既存publisherがあり、競合対策も必要です。実機publishは未実装のままです。ベンダーコードは本リポジトリへ転載しません。

## ツールとチャットの実行

モックでは `move_forward`、`move_backward`、`move_left`、`move_right`、`rotate_left`、`rotate_right`、`move_for`、`stop` を登録します。実機バックエンドでは移動・停止ツールを登録しません。

方向別ツールは正の速度と必須の継続時間を受け取り、符号と軸を決めてMotionExecutorへ渡します。移動はバックグラウンドで実行し、開始応答と完了状態を区別します。状態は `idle`、`running`、`completed`、`cancelled`、`failed` で、失敗理由も保持します。

チャット中は背景スレッドから速度ログを出さず、入力プロンプトを保ちます。`/status` と `/stop` はLLMを経由せず実行します。モックの `move` コマンドは指令ログを表示し、終了を待ちます。テストは通信モック・仮想時計・テスト用LLMを使用し、実機と外部LLM APIへ接続しません。
